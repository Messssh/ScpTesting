# Deep Simulation Systems - Architecture & Implementation Details\n\n## System Overview\n\nThis document provides technical details on how each of the 10 systems is implemented and how they interact.\n\n---\n\n## 1. NPC System (npc-system.js)\n\n### Core Classes\n\n```javascript\nclass NPC {\n  constructor(typeId, x, y, name)\n  tick(dt)                    // Called every frame\n  assignJob(job, target)      // Set NPC's current job\n  isAvailable()               // Can work?\n  getProductivity()           // 0-1 multiplier\n  getPriorityNeed()          // What does NPC need most?\n}\n```\n\n### NPC States\n- **IDLE**: Deciding on next action\n- **WALKING**: Moving to destination\n- **WORKING**: Performing job task\n- **WAITING**: Standing by\n- **RESTING**: In break room\n- **INJURED**: Requires medical attention\n- **STRESSED**: High stress state\n\n### Needs Degradation\n```\nEnergy:   -0.5 per second (halts at 0)\nHunger:   +0.3 per second (caps at 100)\nStress:   +0.01/sec (or +0.1 if morale < 40)\nMorale:   100 - (stress*0.3 + hunger*0.2)\n```\n\n### Job Types\n- RESEARCHING (scientists)\n- TESTING (Class-D)\n- HEALING (doctors)\n- PATROLLING (security)\n- REPAIRING (engineers)\n- RESTING, EATING (all)\n- ESCORTING (security)\n- DEPLOYING (MTF)\n\n### Productivity Calculation\n```\nproductivity = 1.0\nproductivity *= (1.0 - (energy == 0 ? 0.5 : 0))\nproductivity *= (1.0 - (hunger > 70 ? 0.3 : 0))\nproductivity *= (1.0 - (stress > 70 ? 0.4 : 0))\nproductivity *= (morale / 100)\nreturn max(0, productivity)\n```\n\n---\n\n## 2. Power System (power-system.js)\n\n### Power Budget Algorithm\n\n```\nSupply Calculation:\n  supply = BASE_FREE_SUPPLY (20 MW)\n  for each generator: supply += power_output * (health/100)\n  if electrical_rooms: supply *= (1 + distribution_bonus)\n\nDemand Calculation:\n  demand = sum of all room power consumption\n\nDeficit Handling:\n1. Use backup generators if deficit > 0\n2. Draw from batteries if still deficit\n3. If still deficit: prioritize rooms\n```\n\n### Power Priority (Priority = 1 highest, 9 lowest)\n```\n1 (Critical):    electrical, containment, heavy\n2 (High):        control, security, medical\n3 (Medium):      lab, barracks\n4 (Medium-Low):  holding, engineering\n5 (Low):         office\n6 (Lowest):      breakroom, storage\n0 (Optional):    corridor\n```\n\n### Room Degradation Rates\n```\nBase:              0.2% per tick\nGenerator:         1.0% per tick\nUnpowered:         3.0% per tick (10x normal)\nDangerous SCP:     +1.0% per tick (for containment)\n```\n\n### Battery Mechanics\n```\nCapacity per battery room: 60 MW\nDegraded capacity: 60 * (health / 100)\nCharge rate (surplus): supply - demand * 0.5\nDischarge rate (deficit): min(deficit, battery_charge)\n```\n\n---\n\n## 3. SCP Behaviors (scp-behaviors.js)\n\n### Behavior Framework\n\n```javascript\nclass SCPBehavior {\n  onContain(scp)                    // Initialization\n  onBreach(scp)                     // Breach event\n  tickContained(scp, dt, grid, staff)  // Per-frame while contained\n  tickBreach(scp, dt, grid, staff)     // Per-frame while breached\n  getProperties(scp)                // UI display properties\n}\n```\n\n### SCP-173 Implementation\n```\nObservation System:\n  - Count staff within 50px = observers\n  - If observers == 0: Can move\n  - Each unobserved tick: ~1% chance to teleport\n  - On teleport: 30% chance to kill nearby staff\n\nProperties Tracked:\n  - observersCount: Staff watching\n  - observationTime: Total time observed\n```\n\n### SCP-096 Implementation\n```\nRage Trigger:\n  - 2% chance per tick to enter rage\n  - Rage duration: 30 seconds\n  - Chase speed: 50 pixels/sec\n  - Kill range: 30px\n\nBehavior:\n  - Pursues angryTarget relentlessly\n  - Kills on contact\n  - Resets after duration expires\n```\n\n### SCP-049 Implementation\n```\nHunting:\n  - Searches for Class-D within 200px\n  - Moves toward them at 25 px/sec\n  - Infects on contact (30px range)\n\nInfection:\n  - Victim added to infected list\n  - Stress +50\n  - Can spread to other Class-D\n```\n\n### SCP-999 Implementation\n```\nMorale Aura:\n  - Staff within 150px: +5 morale/sec\n  - Stress reduction: -2/sec in range\n  - No combat mechanics\n```\n\n### SCP-682 Implementation\n```\nDamage:\n  - Wall damage accumulates: +0.5/sec\n  - Breach at 100 damage\n  - Adaptation increases: +0.1 level/sec\n\nBreach Behavior:\n  - Destroys adjacent rooms: -2 health/sec\n  - Moves toward exits\n  - Can adapt to obstacles\n```\n\n---\n\n## 4. Research Tree (research-tree.js)\n\n### Node Structure\n```javascript\nclass ResearchNode {\n  id: string                // Unique identifier\n  name: string              // Display name\n  category: string          // Research category\n  cost: number              // Research points needed\n  duration: number          // Time in seconds\n  prerequisites: string[]   // Required research IDs\n  completed: boolean        // Completion status\n  progress: number          // 0-100%\n  unlocks: string[]         // Items/rooms unlocked\n  bonuses: object           // Gameplay bonuses\n}\n```\n\n### Categories & Counts\n- **Containment**: 4 researches (basic → heavy upgrade)\n- **Security**: 3 researches (surveillance → elite MTF)\n- **Personnel**: 3 researches (training → rapid response)\n- **Engineering**: 3 researches (maintenance → reinforced)\n- **Medical**: 3 researches (field medicine → mental health)\n- **Power**: 3 researches (batteries → nuclear)\n\n### Progress Calculation\n```\nprogress += (dt / node.duration) * 100\nif progress >= 100: mark as completed\n```\n\n### Unlock System\n```\nEach research can unlock:\n  - New room types\n  - Staff upgrades\n  - Equipment items\n  - Gameplay bonuses (morale, power efficiency, etc.)\n```\n\n---\n\n## 5. Events System (events-system.js)\n\n### Event Framework\n\n```javascript\nclass FacilityEvent {\n  id: string\n  type: EVENT_TYPES\n  severity: 'low' | 'moderate' | 'high' | 'critical'\n  active: boolean\n  startTime: number\n  duration: number\n  affectedAreas: []\n  effects: {}\n}\n```\n\n### Severity → Duration Mapping\n```\nlow:       15 seconds\nmoderate:  30 seconds\nhigh:      45 seconds\ncritical:  60 seconds\n```\n\n### Event Effects\n\n**Power Failure**\n- All rooms: powered = false\n- Duration: 30s\n\n**Fire**\n- 5 random rooms catch fire\n- Health: -50\n- Duration: 30s\n\n**Class-D Riot**\n- All Class-D become aggressive\n- Stress: 100\n- Duration: 45s\n\n**Generator Explosion**\n- Destroy first generator found\n- Health = 0\n- Fire = true\n\n**Earthquake**\n- 10% of cells take damage\n- Health: -30 per cell\n- Duration: 30s\n\n**Gas Leak**\n- All staff take damage: -10 HP\n- Stress: +30\n- Duration: 30s\n\n**Multiple Breach**\n- 1-3 random SCPs breach\n- Triggers lockdown escalation\n\n### Event Triggering\n```\nCheck frequency: 1 per second\nEvent probability: 1% per check\n= ~0.01 events/sec = 1 event per 100 seconds (on average)\n```\n\n---\n\n## 6. Door & Lockdown System (door-lockdown-system.js)\n\n### Door Framework\n\n```javascript\nclass Door {\n  row, col: number          // Grid position\n  type: DOOR_TYPES          // standard/security/heavy/blast\n  clearanceLevel: number    // 0-5 clearance required\n  open: boolean             // Current state\n  locked: boolean           // Can't open when locked\n  powered: boolean          // Requires power\n  animation: number         // 0-1 animation progress\n  power: number             // Power consumption\n}\n```\n\n### Clearance Levels\n```\n0: PUBLIC (everyone)\n1: STAFF (employees only)\n2: SECURITY (guards+)\n3: RESEARCH (scientists+)\n4: SITE_COMMAND (directors+)\n5: O5 (O5 council only)\n```\n\n### Lockdown Levels\n```\n0: None              - All doors unlocked\n1: Yellow Alert      - Non-essential rooms locked\n2: Red Alert         - Security zones sealed\n3: Full Lockdown     - All doors except emergency sealed\n```\n\n### Door Power Requirements\n```\nstandard:  1 MW\nsecurity:  2 MW\nheavy:     4 MW\nblast:     6 MW\n```\n\n### Lockdown Triggers\n```\nAny SCP breach → Yellow Alert\nMultiple breaches → Red Alert\nMajor emergency → Full Lockdown\n```\n\n---\n\n## 7. Incident Reporting (incident-reporting.js)\n\n### Report Structure\n\n```javascript\nclass IncidentReport {\n  id: string                // Unique ID\n  type: INCIDENT_TYPES      // Type of incident\n  timestamp: number         // When it occurred\n  day: number               // Facility day\n  scps_involved: string[]   // SCP IDs\n  casualties: number        // Staff killed\n  property_damage: number   // Rooms destroyed\n  financial_cost: number    // Repair costs\n  time_to_recontain: number // Recontainment time\n  cause: string             // Root cause\n  severity: string          // minor/moderate/severe/critical\n  status: string            // ongoing/resolved\n}\n```\n\n### Incident Types\n```\nBREACH              - SCP containment failure\nCASUALTY            - Staff killed\nFIRE                - Facility fire\nPOWER_FAILURE       - Grid failure\nPROPERTY_DAMAGE     - Room destruction\nUNAUTHORIZED_ACCESS - Clearance violation\nEXPERIMENT_FAILURE  - Test gone wrong\n```\n\n### Report Lifecycle\n```\n1. Create report when incident begins\n2. Track duration and casualties\n3. Close report with final metrics\n4. Store in permanent log\n```\n\n---\n\n## 8. Facility Statistics (facility-statistics.js)\n\n### Tracked Metrics\n\n```javascript\ntotalStaff: number\ntotalSCPs: number\ncasualties: number\nresearchCompleted: number\ntotalIncome: number\ntotalExpenses: number\ncontainmentRating: number    // 0-100\npowerUsage: number\nfacilityEfficiency: number   // 0-100\nactiveEmergencies: number\nbreachesHandled: number\naverageStaffMorale: number\nstaffTurnover: number\nscpBreaches: number\nuptime: number               // 0-100\n```\n\n### Calculations\n\n**Efficiency**\n```\nbaseEfficiency = 100\nstaffFactor = min(1, totalStaff / 50)\nmoraleFactor = averageStaffMorale / 100\nefficiency = baseEfficiency * (staffFactor * 0.5 + moraleFactor * 0.5)\n```\n\n**Containment Rating**\n```\nrating = 100\nrating -= scpBreaches * 10\nrating -= (casualties / totalStaff) * 50\nrating = max(0, min(100, rating))\n```\n\n**Risk Level**\n```\n80-100: LOW\n60-79:  MODERATE\n40-59:  HIGH\n0-39:   CRITICAL\n```\n\n---\n\n## 9.
